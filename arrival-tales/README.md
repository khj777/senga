# 도착동화 — 길의 끝에서, 이야기의 끝까지

아이와 함께 이동하는 가족을 위한 차량용 오디오 동화 시제품. 남은 이동 시간이 달라지면 이야기의 선택 장면을 다시 구성하고, 핵심 사건과 결말을 보존합니다.

## 문제와 제품

목적지에는 도착했지만 듣던 이야기는 끝나지 않은 상황에서 출발했습니다. 부모는 재생을 끊어야 하고 아이는 결말을 기다립니다. 도착동화는 차의 내비게이션 ETA를 이야기 편집의 입력으로 사용합니다.

핵심 이용자는 유아·초등 저학년 자녀와 이동하는 보호자입니다. 초기 범위는 원작 오디오 동화에 한정합니다. 실행 중 생성형 AI 호출 없이 미리 작성한 핵심 장면과 선택 장면을 조합합니다. 아동 대상 원문과 음성의 전문 검수는 후속 작업입니다. 독창성·수상 가능성·사용자 수요를 검증한 것은 아닙니다.

## 이번에 실제 구현한 것

- 의존성 없는 브라우저 앱: 데스크톱과 모바일 대응
- 원작 ‘달을 배달하는 고래’: 핵심 4장면 + 선택 4장면
- ETA에 맞는 장면 선택, 완주한 장면 재생 방지, 급격한 ETA 감소 시 연결형 짧은 결말
- 0분 도착 시 음성을 멈추고 읽을 수 있는 도착 카드
- 재생·일시정지·다음 장면·처음부터·실시간/12배속/30배속 시연
- 브라우저 SpeechSynthesis를 사용하는 한국어 음성 읽기와 미지원/오류 시 화면 시연
- 내비 음성 우선순위의 시뮬레이션, 같은 문장부터 재개
- 주행 화면의 정보 축소, 이야기 원문, 제품 아이디어 노트

## 시연 순서 (약 1분)

1. 재생을 누릅니다. 기본은 음성 없는 12배속 장면 시연입니다.
2. ‘길이 뚫렸어요’: ETA를 5분으로 바꿉니다. 시작 전에 눌렀다면 핵심 4장면만 남습니다.
3. ‘조금 막히네요’: ETA를 18분으로 바꿉니다. 아직 지나가지 않은 선택 장면이 추가됩니다.
4. ‘길 안내가 나와요’: 약 5초간 이야기 재생이 멈추고 이후 이어집니다.
5. ‘곧 도착해요’: 2분에 맞는 짧은 결말로 전환합니다.
6. 음성을 듣고 싶다면 ‘음성 켜기’를 누릅니다. 실시간으로 전환되며, 기기에 설치된 한국어 음성에 의존합니다.

## 사실과 시뮬레이션의 경계

실제 Pleos SDK, 실차, Android 에뮬레이터와 연결하지 않았습니다. ETA 및 오디오 포커스는 버튼과 슬라이더로 입력하는 데모 신호입니다. 웹 시제품이며 APK가 아닙니다.

장면 `minutes`는 데모 편집 예산입니다. 본문은 축약 시연 원문이므로 실제 음성 길이와 일치하지 않습니다. 상용 오디오는 녹음 파일의 측정된 길이로 교체해야 합니다. 도착 시각에 정확히 끝난다는 보장은 하지 않습니다. 갑작스러운 도착에는 즉시 멈추고 도착 카드를 표시합니다. 음성 모드에서 사용자가 배속 시뮬레이션을 선택하면 녹음이 끝나기 전에 도착 이벤트가 발생할 수 있습니다.

현재 사용자의 일시정지와 데모 길 안내 중에는 시뮬레이션 시간이 함께 멈춥니다. 실제 앱에서는 차량 ETA 입력은 계속 갱신되어야 하며, 문장 경계의 재계획·오디오 포커스 복귀 시 잔여 예산 조정을 구현해야 합니다.

사이트에는 계정, 위치 수집, 외부 AI API, 분석 도구가 없습니다. 글꼴은 Google Fonts를 사용하고 로컬 대체 글꼴이 지정되어 있습니다. 기기 음성 엔진의 처리 방식은 브라우저/OS 설정에 따릅니다.

## 실행

Node.js 22 이상:

```text
node server.mjs
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. ES 모듈을 쓰므로 `dist/index.html` 파일을 더블클릭하는 대신 HTTP 서버를 사용합니다. 배포 결과물은 `dist/`입니다.

**서버 없이 체험:** 함께 제공한 `도착동화-시제품.html`을 브라우저에서 열면 됩니다. CSS·SVG·JavaScript가 한 파일에 포함되어 있습니다. 외부 Google Fonts가 없어도 대체 글꼴로 동작합니다. `node package-local.mjs`로 소스에서 다시 만들 수 있습니다.

## 검증

```text
node --check dist/app.mjs
node --test --test-isolation=none tests/engine.test.mjs tests/controller.test.mjs
```

엔진 테스트 12개는 ETA 0/2/5/9/14/20, 소수/잘못된 입력, 장면 순서와 예산, 시간 감소/증가, 완료 상태를 검증합니다. 컨트롤러 회귀 테스트 8개는 길 안내 우선, 늦게 도착한 음성 콜백 무시, 사용자 일시정지 의도, 짧은 결말 보존 등을 검증합니다. 총 20개가 통과했습니다. 브라우저에서도 시간 단축·증가, 안내 중단·재개, 짧은 결말, 종료·재시작, 주행 화면 및 원문 대화상자를 점검했습니다. 기기에서 실제 소리가 들리는지에 대한 청각 검증과 Pleos 실기기 검증은 별개입니다.

## 다음 제품 검증

1. Pleos 에뮬레이터에서 NaviHelper ETA 콜백을 수신하는 작은 Android 앱부터 실행합니다.
2. 미디어 서비스와 Android 오디오 포커스를 연결하고 내비 음성과 경쟁하지 않는지 확인합니다.
3. 실제 길이를 측정한 5·10·15분 분량 오디오를 제작해 문장 경계 편집과 도착 오차를 측정합니다.
4. 가족 사용자에게 일반 오디오와 비교해 이야기 만족도, 도착 시 중단 빈도를 확인합니다.

공식 문서에서 확인한 API 접근 조건과 구현 경로는 `PLEOS-INTEGRATION.md`를 참조하세요.


## 제출 상태와 APK

현재 저장소는 **웹 시제품 소스**입니다. Android APK는 아직 없으며, Pleos SDK를 실제로 실행하거나 에뮬레이터에서 ETA를 수신한 결과물은 아닙니다. `apk/README.md`에 현황을 기록했습니다. 실행 가능한 release APK가 준비되면 `apk/` 또는 GitHub Releases에 추가하고 이 문서에 정확한 경로와 테스트 환경을 적습니다.

## 테스트 환경과 설정

- 개발 확인 환경: Windows, Chromium 계열 브라우저
- 소스 실행 및 자동 테스트: Node.js 22 이상, 별도 패키지 설치 불필요
- 외부 API 키나 로그인 불필요
- 음성 기능: 브라우저 SpeechSynthesis 및 한국어 음성 지원 필요
- 네트워크가 없으면 외부 글꼴 대신 시스템 대체 글꼴 사용
- 차량 데이터와 길 안내는 시뮬레이션이며 실제 Android AudioFocus 검증은 미완료

## 제작 및 검증 범위

코드, 동화 원문, 일러스트와 문서는 생성형 AI의 도움을 받아 제작했습니다. 자동 테스트 통과는 실제 차량 안전성, 사용자 만족도 또는 콘텐츠 권리의 검증을 의미하지 않습니다. 현재 원작 한 편의 규칙 기반 시제품이며, 사용자 조사 및 실측 음원 길이 기반의 완주 검증은 후속 작업입니다.

참가자 신청서, 개인정보 동의서, 연락처, 서명, 로컬 SDK 배포 파일과 개발 환경 설정은 저장소에 포함하지 않습니다. GitHub 계정 및 커밋 작성자 정보는 파일 본문과 별개로 표시될 수 있으므로 제출 전 공식 익명 심사 지침에 맞는지 확인해야 합니다.
